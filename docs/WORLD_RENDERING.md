# World rendering through Phase 17

Phase 15 proved Cubic's first `server chunks -> semantic state -> CPU mesh -> GPU` path. Phase 16 preserves that ownership/scheduling path while replacing diagnostic colors/cubes with exact-version vanilla blockstate, model, and texture inputs. See `BLOCK_RESOURCES.md` for the resource boundary and current presentation limits.

## Semantic inputs

The protocol-775 Configuration Registry Data codec follows the vanilla 26.1.2 registration verified from `ClientboundRegistryDataPacket` and `RegistrySynchronization.PackedRegistryEntry`: registry identifier, bounded entry list, entry identifier, and optional bounded network NBT. For `minecraft:dimension_type`, Cubic extracts integer `min_y` and `height`. Vanilla's `DimensionType` codec and constructor require height of at least 16, height divisible by 16, and `min_y` divisible by 16; Cubic validates those rules before activating a world. Section zero maps to `min_y / 16`, so Overworld and Nether do not require hardcoded names or heights.

Runtime block states remain typed numeric IDs because that is what chunk palettes carry. At World Mode startup, Cubic loads exact Phase 11 game data, verifies its client provenance against Phase 10 metadata, and resolves each state to the official blockstate/model resources. Air-family states remain non-rendered; unknown or unresolved states use Cubic's visible generated fallback rather than silently becoming air.

## Ownership and work scheduling

The network task remains sole owner of canonical `WorldState`. It publishes a coalescing mailbox containing the latest timed pose sample, reset generation, geometry, and at most one load/unload delta per bounded chunk coordinate. Loaded chunks use immutable `Arc` snapshots, so ordinary publication is a cheap reference clone rather than a deep section clone. Live mutation uses copy-on-write, preserving an in-flight revision for stale-result rejection. The complete world is never cloned per frame and no lock is held across I/O or meshing.

`cubic-render` keeps only render-side chunk references and GPU meshes. A bounded pool of up to four workers receives jobs containing the center chunk plus four horizontal neighbors, emits only exposed model faces, and creates the finished vertex/index buffers through a cloned thread-safe wgpu device. Workers share immutable exact-version render data. Dirty chunks remain coalesced by coordinate; available worker slots select the nearest chunk to the current authoritative player chunk without sorting the complete world, with coordinate order as a deterministic equal-distance tie-breaker. A changed authoritative pose affects the next selection, while a reset clears all pending render-side state before establishing the new origin. Neighbor arrival, replacement, unload, or live block mutation marks both sides dirty. Reset generations discard stale results and immediately clear prior-dimension CPU/GPU state. The event loop validates/installs at most 16 results and dispatches at most eight new jobs under one four-millisecond foreground deadline so variable-cost village geometry yields back to winit input processing. Periodic progress logging is written through a bounded background writer rather than blocking the event loop.

Static resource work is prepared once into a direct `RuntimeBlockStateId` table. The runtime path borrows state/model data and already-resolved atlas regions rather than cloning model trees or resolving strings per block. Provably opaque full cubes whose six neighbors are also full occluders exit before model selection, transforms, UV work, or output growth. Other models retain conservative face-by-face handling. Aggregate progress diagnostics distinguish loaded chunks from visible meshes and report bounded queue/worker/counter/timing state without per-mesh spam.

Each nonempty chunk mesh owns vertex/index GPU buffers. Vertices carry atlas UV, tint/shade, and material classification. The sRGB atlas uses nearest magnification to preserve pixel art. Opaque and translucent terrain use linear minification to reduce distant full-resolution shimmer, while alpha-tested cutouts use nearest minification to preserve narrow coverage; bounded mip-atlas generation remains future work. Cutout fragments are alpha-tested, and perspective/depth behavior remains unchanged. Minecraft zero-thickness cross models deliberately carry opposite-winding faces on each plane; terrain back-face culling selects only the view-facing face instead of depth-writing both coplanar faces and producing visible fighting. Synthetic cross-model tests preserve that geometry. In Phase 17 the camera consumes timed previous/current locally predicted poses. It uses vanilla-style render partial ticks to interpolate x/y/z at display rate while leaving collision and packets on the 20 Hz simulation. Phase 18C presents discrete physical eye-height changes through a separate generic, time-based, reversible transition suitable for swimming and future poses. Sequenced cumulative mouse preview remains independent and is rebased against each simulation acknowledgement. Corrections, resets, and first samples snap both presentation endpoints. The movement controller is the sole pose source after prediction is seeded, so unrelated chunk or semantic world updates cannot replay a stale authoritative position. The renderer still owns no physics and sends no packets. Resize recreates only the depth target and does not remesh chunks. The window title reports dimension, geometry, predicted pose, loaded/meshed chunk counts, and each dirty coordinate once; in-flight coordinates are no longer double-counted as both dirty and pending.

Minecraft block coordinates are passed to the renderer unchanged: +X is east, +Y is up, and +Z is south. Chunk-local X/Z use Euclidean division so negative chunk boundaries remain correct. Minecraft yaw 0 faces +Z, +90 faces -X, -90 faces +X, and positive pitch looks downward. The stable camera basis derives right directly from yaw and up from right×forward; it therefore remains finite and continuous at exact pitch -90/+90 instead of crossing pole-aligned forward with a fixed world-up vector. At the render boundary this basis is converted to a right-handed view space whose camera-forward direction is -Z; when facing south, screen-right is west (-X), avoiding a reflected world. Standing and sneaking camera eye heights remain explicit and separate from feet position and collision-box height.

Minecraft `uvlock` is face-local. Cubic now reproduces the model baker's inverse face transform: it rotates the source face's U/V basis through blockstate X then Y, expresses that basis in the destination face, and applies the inverse orthogonal transform to the UVs. The earlier transformed-corner heuristic selected the opposite quarter-turn for source-down faces transformed by X=180 then Y=90/270, which is the north/south top-half stair defect. A resource-backed four-facing stair fixture protects the generic correction; there is no stair-name exception. Generated UVs likewise follow the direction-specific 26.1.2 face formulas. Door models continue through the same centre-pivot blockstate transform and remain inside their block cell; no door-specific visual offset is introduced.

Faces are emitted only when the adjacent semantic state is air or the neighbor is not loaded. Section boundaries use the same absolute lookup as ordinary blocks. Horizontal chunk neighbors are included in each bounded mesh job; arrival, replacement, and unload remesh both sides so temporary boundary faces converge. A `WorldContents` generation reset drops render-side chunk references and GPU buffers immediately, and late worker results from the old generation are ignored. The renderer retains one immutable reference and at most one GPU mesh per loaded chunk; Phase 30 will establish explicit global budgets and deeper streaming policy.

The final fluid-side visibility correction preserves vanilla's reverse winding for ordinary horizontal sides, with back-face culling selecting only one winding at a pixel. Translucent terrain uses the verified 26.1.2 depth-writing `LESS_EQUAL` policy, preventing farther reverse-facing fluid boundaries from showing through nearer water. A side hidden by a neighbouring opaque full-cube face is omitted before meshing, removing its near-coplanar fluid/block boundary while retaining boundaries beside transparent and partial models. Side vertices and UVs follow `FluidRenderer`'s literal `top-left, top-right, bottom-right, bottom-left` order. Cubic's former cyclic shift preserved the outline and winding but selected the opposite outward triangle diagonal on every sloped trapezoid; clipped cells repeat the canonical order and share interpolated boundaries exactly. Partial-model clipping now extracts the boundary of the retained fluid volume across the selected model's bounded axis-aligned element grid: occupied outer subdivisions remain absent, while an open subdivision adjoining model volume emits its inset internal boundary. This fixes the live waterlogged inner-stair case whose retained north-west quarter had a top but no south/east walls; it is model-topology driven and contains no block-name or runtime-ID branch. Surface heights, lower edge, UV scale, flow/current rules, falling geometry, neighbour occlusion, and ordinary fluid decoding are unchanged.

Vanilla renders honey's full outer shell and inset translucent cube through its depth-writing translucent terrain layer after per-quad sorting. Cubic still deliberately defers the general per-quad sorter, so the exact-version resource adapter resolves that nested-shell model to a generic layered-translucent policy: alpha blending and depth testing remain enabled, but those layered model quads do not write depth and therefore do not lose the inset shell behind the first outer face. Water, glass, ice, slime, and ordinary translucent terrain retain the accepted depth-writing policy. This compatibility material is carried by prepared faces and a separate bounded index batch; the generic GPU renderer contains no Minecraft block-name branch.

## Phase 18 presentation suspension

Chat presentation does not freeze the world. Render-side chunk snapshots and latest revisions continue to coalesce, but no world surface pass calls `prepare`, so no new mesh work is dispatched and no terrain frame is submitted. The egui chat surface remains event-driven. Returning to Play resumes the same bounded workers and selects dirty coordinates nearest the latest live player chunk first; no reconnect, chunk reload request, or full-world sort is introduced.

## Development command and limits

```powershell
$env:CUBIC_LOG_LEVEL='debug'
cargo run -p cubic-app -- world localhost:25565 --username CubicTest2
```

World Mode is a separate offline-development entry point and expects the Phase 11 artifact at `%LOCALAPPDATA%\Cubic\generated\game-data\26.1.2\game-data.json`. Normal clear-frame, Status, Login, authenticated networking, and Chat Mode commands are unchanged. No server is contacted by automated tests.

Temporary Phase 18B fluid diagnostics are disabled by default. `CUBIC_DEBUG_FLUID_FACES=1` replaces fluid texture presentation with direction colours only in the diagnostic build path: top magenta, north red, south green, east blue, west yellow, and bottom cyan; clipped/subdivided faces are mixed toward white. `CUBIC_DEBUG_FLUID_MESH=1` writes bounded DEBUG records for fluid cells within `CUBIC_DEBUG_FLUID_RADIUS` blocks of the current player (default 6, clamped to 1–32). Records include fluid state and heights, all four side decisions, final vertices/UVs/indices/windings/batches, invariant results, and the final GPU-buffer draw ranges. At most 32 cells per mesh, 128 quads per cell, and 128 cells for the process are retained/logged. These switches do not alter the default mesh bytes or fluid rules and are intended only for short localhost diagnosis.

The required real localhost acceptance against offline-mode vanilla Java 26.1.2 passed. Cubic rendered 329 real Overworld chunks with correct depth and vanilla-matching orientation, survived aggressive resize and minimize/restore, cleared old render state across Overworld -> Nether -> Overworld, and rendered each dimension with its authoritative geometry. The final near-player-first loading-order retest also passed, with substantially improved visible mesh completion and stable terrain. World Mode shut down cleanly; the separate Chat Mode retained bidirectional chat and no world chunks. No warning, error, panic, or stale cross-dimension geometry was observed.

Phase 16 final visual acceptance passed against localhost vanilla Java 26.1.2, Phase 18's Play/Chat switching is accepted, and Phase 18B rendering fidelity passed its final localhost acceptance: Configuration biome metadata and chunk palettes drive blended tint; complete bounded light layers, four-sample vertex light, model-controlled AO, and corner-neighbour occlusion drive vertex brightness; semantic water/lava states generate neighbour-aware sloped surfaces; and opaque/cutout geometry is submitted before far-to-near translucent chunk batches. Vanilla's atlas is raw RGBA8 and its terrain shader multiplies encoded normalized texel, tint and light values. Cubic retains an sRGB atlas/surface but explicitly reconstructs that encoded-domain product in the shader between the two hardware transfer conversions; this avoids both the earlier double-linearized dark/saturated result and the later physically-linear washed-out result. Water uses the same pipeline without a blue multiplier and takes the maximum light at its cell and the cell above, matching FluidRenderer rather than sampling a horizontal neighbour. Flow sides map one block to normalized sprite coordinates `0..0.5`; because the animated frame is 32 pixels wide/high, that is exactly 16 source texels per full block side. V remains tied to physical height, including clipped subdivisions, and an exposed bottom plus its four sides share vanilla's `0.001` lower edge so the clipping grid cannot reopen a seam. Ordinary horizontal fluid sides are emitted in both windings, matching `FluidRenderer`; this keeps the complete trapezoid visible through the fluid volume beneath an asymmetric top edge instead of exposing the top quad's diagonal. Fluid surface sampling is deliberately separate from current-force sampling: open cells contribute `0`, collision-derived legacy-solid cells contribute `-1` and are excluded, and only positive cardinal samples cause a diagonal lookup. Samples at or above `0.8` retain the current renderer's tenfold weighting. A local fluid cell with matching fluid above short-circuits all four corners to full height, preventing falling columns from becoming pyramids; otherwise a source/falling amount-eight cell has own height `8/9`, flowing levels use `(8-level)/9`, and the top quad retains the `0.001` render offset. Top still/flow selection and orientation continue to use the already accepted horizontal flow vector. Vanilla directional shade remains symmetric by axis (top 1.0, bottom 0.5, north/south 0.8, east/west 0.6). Scaffolding is an exact-version cutout material, preserving transparent net faces without shader special cases. Cutout fragments use a nearest minification sampler so narrow alpha-tested strands are not averaged with transparent texels and discarded at oblique angles; opaque/translucent terrain retains linear minification while coverage-preserving mip generation remains deferred. Waterlogged partial models expose selected axis-aligned element bounds; both top and boundary-side fluid quads are subdivided at those bounds and solid cells are suppressed rather than separated with a larger arbitrary epsilon. Exact-version XZ/XYZ vegetation offsets use the vanilla position seed; short grass/fern can move downward, while double-height grass/fern retain their XZ-only registration. Shade-disabled, unculled cross-model faces preserve their resource metadata and sample their own block light so opposite sides do not pick unrelated neighbour light. Animated still/flow atlas subregions advance by elapsed 20 Hz resource ticks without mesh rebuilds. Per-quad translucency sorting, generated mip levels, complete clipping for arbitrarily rotated model elements, pixel-identical partial-model smooth-light weighting, Phase 24 sky/day/weather lightmaps and underwater camera fog/colour, frustum/occlusion optimization, and entities remain deferred.
