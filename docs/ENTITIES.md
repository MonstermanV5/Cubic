# Phase 21 entity state (accepted)

The accepted Phase 20 checkpoint is independent of this uncommitted Phase 21 work. The current reference is vanilla Java 26.1.2 / protocol 775; it is not a permanent cross-version packet mapping.

`cubic-protocol::bootstrap::v775::entity` owns the verified packet IDs and current wire layouts. Mojang's local 26.1.2 `packets.json` gives `add_entity` 0x01, `entity_position_sync` 0x23, `move_entity_pos` 0x35, `move_entity_pos_rot` 0x36, `move_entity_rot` 0x38, `remove_entities` 0x4d, `rotate_head` 0x53, `set_entity_motion` 0x65, `teleport_entity` 0x7d, and `update_attributes` 0x83. Read-only inspection of the installed client confirms the unified spawn packet, field order, 1/4096 relative-position deltas, byte angles, low-precision vector velocity, and VarInt-bounded removal collection. Protocol IDs do not appear in generic world/render state.

The World Mode session resolves numeric entity types through the exact-version generated `minecraft:entity_type` registry. It immediately applies server transforms and velocity to a world-owned `EntityStore`. Entity IDs map to generation-tagged stable handles; removal and ID reuse invalidate old handles. Spawns, removal, disconnect, Configuration, Enter World, and respawn have explicit lifecycle clearing. Network authority is never updated by render frames. A separate 150 ms bounded interpolation target supports arbitrary frame rates, shortest-path angle interpolation, and large-teleport snaps without extrapolating during packet gaps.

The network-to-render mailbox coalesces entity deltas by entity ID, independently of chunk meshes. If a stalled renderer lets 4,096 distinct deltas accumulate, the mailbox replaces those disposable deltas with a bounded snapshot of the authoritative store. The diagnostic renderer draws at most 256 remote entity boxes using exact default 26.1.2 `EntityType` width/height and labels them with type/ID. `tools/EntityDump.java` reproducibly extracts the 157 registered dimensions into `crates/cubic-version/data/26.1.2/entity-data.json`; the typed version selector validates count, IDs, uniqueness, and finite nonnegative extents. Missing data uses a bounded diagnostic fallback. Dynamic pose-, age-, scale-, slime-, and interaction-dependent dimensions remain deferred. This is not a mob/player model renderer. The local controlled player stays in the existing separate prediction path and is not duplicated as a remote entity.

`set_entity_data` now decodes and retains every current registered serializer ID 0–42 by accessor, replacing prior values. The exact official 26.1.2 `EntityDataSerializers` registration order is: 0 BYTE; 1 INT; 2 LONG; 3 FLOAT; 4 STRING; 5 COMPONENT; 6 OPTIONAL_COMPONENT; 7 ITEM_STACK; 8 BOOLEAN; 9 ROTATIONS; 10 BLOCK_POS; 11 OPTIONAL_BLOCK_POS; 12 DIRECTION; 13 OPTIONAL_LIVING_ENTITY_REFERENCE; 14 BLOCK_STATE; 15 OPTIONAL_BLOCK_STATE; 16 PARTICLE; 17 PARTICLES; 18 VILLAGER_DATA; 19 OPTIONAL_UNSIGNED_INT; 20 POSE; 21 CAT_VARIANT; 22 CAT_SOUND_VARIANT; 23 COW_VARIANT; 24 COW_SOUND_VARIANT; 25 WOLF_VARIANT; 26 WOLF_SOUND_VARIANT; 27 FROG_VARIANT; 28 PIG_VARIANT; 29 PIG_SOUND_VARIANT; 30 CHICKEN_VARIANT; 31 CHICKEN_SOUND_VARIANT; 32 ZOMBIE_NAUTILUS_VARIANT; 33 OPTIONAL_GLOBAL_POS; 34 PAINTING_VARIANT; 35 SNIFFER_STATE; 36 ARMADILLO_STATE; 37 COPPER_GOLEM_STATE; 38 WEATHERING_COPPER_STATE; 39 VECTOR3; 40 QUATERNION; 41 RESOLVABLE_PROFILE; 42 HUMANOID_ARM. There is no valid-but-unsupported fallback. The terminator is 0xff; malformed values, unknown IDs, and trailing data fail structurally.

Complex values reuse the existing trusted text-component and Phase 20 ItemStack/component-patch decoders. Components retain structured text and wire data; block states retain global state ID plus stable block identity/properties; particles retain options for every current non-simple type (block, power, dust, transition, spell, colour, item, vibration, trail, shriek) with a 256-entry list cap. Pose and small enums retain ordinal and semantic name. Living-entity references retain UUID identity, not a recyclable protocol ID. Profiles retain bounded complete/partial identity, properties, and optional skin fields without remote skin fetching. Metadata is capped at 64 KiB per wire value and 128 KiB retained per entity.

The 12 animal/sound variant serializers, villager data, and attributes use zero-based `holderRegistry` IDs. Painting instead uses a distinct holder codec: zero is a direct painting definition, positive values refer to connection registry ID `wire - 1`; the direct value is retained. Configuration supplies authoritative connection registry ordering; partial reconfiguration replaces only the supplied mappings. Connection-local IDs become stable semantic identifiers immediately, while absent registry and unknown references fail distinctly. Static exact-version registries support only genuinely static data and offline tests; they are not substituted for missing dynamic connection registries. Optional global positions retain stable dimension identity. Attribute updates retain finite bases and bounded modifiers with zero-based attribute-holder lookup. Entity teleport relative flags, including motion rotation, remain separate from absolute synchronization.

All 43 serializer IDs are covered in one sequential framing fixture plus focused malformed, registry, component, particle, enum, reference, and dimension tests. Controlled vanilla 26.1.2 localhost acceptance confirmed labelled debug boxes and exact default dimensions, spawn/despawn, movement and rotation interpolation, absolute teleports, tracking-range despawn/respawn, reconnect cleanup, and varied live entities without metadata decoder errors or ghost entities. Phase 21 is `[x]`. Entity models, equipment rendering, AI, combat, skin fetching, and animation remain Phase 22 or later.
