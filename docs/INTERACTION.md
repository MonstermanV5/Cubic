# Block Interaction

Phase 19 is in progress. `cubic-world` performs a finite, reach-bounded voxel DDA from the local eye pose and intersects version-selected outline components inside each visited cell. Targeting is separate from physical collision and fluid rendering. The 26.1.2 semantic adapter now distinguishes connection-aware fence outlines from their taller physical collision, uses state-dependent thin button/lever outlines despite their empty physical collision, and carries the complete selected multipart shape to rendering. Air and fluid-only cells are never targetable. Unverified non-colliding visual states retain a conservative selectable full-cell outline.

Survival/adventure targeting uses 4.5 blocks and creative targeting uses 5.0 blocks. These values are semantic `BlockReach` values selected from the authoritative game mode, not renderer constants. The result contains block coordinate, runtime state, face, hit point, distance, and the intersected outline component.

The network-owned 20 Hz controller samples bounded held attack state and bounded use presses. It emits the version-profile's Start/Abort/Stop Destroy and main-hand Use Item On/Use Item packets with a dedicated monotonically increasing interaction sequence. Creative START is immediate when its delay is zero and arms vanilla 26.1.2's five intervening-tick destroy delay. Survival maintains deterministic per-target progress using the explicitly supported empty-hand baseline; target changes abort and restart, release aborts, and zero-progress/unbreakable states never start or finish. The exact 26.1.2 registry places Player Action at `0x29`, Use Item On at `0x42`, and Use Item at `0x43`; the nearby `0x24` entry is Pick Item From Block and must not be confused with Player Action. Block Changed Ack advances bounded interaction acknowledgement state. Focus loss, Chat Mode, reset, and disconnect release attack and clear interaction state. Authoritative Block Update, Section Blocks Update, chunk replacement, unload, and dimension reset remain the source of truth.

The renderer receives only the current semantic target and destroy stage; it never performs a second raycast. Selection uses the target's complete bounded voxel shape and the accepted screen-space external-edge renderer. Survival progress maps to the ten official `minecraft:block/destroy_stage_0` through `_9` runtime textures using `floor(progress * 10)` while progress is below completion. Cubic re-bakes the selected weighted/multipart block model with the same position seed and projects the crack UVs from each transformed face, matching the official sheeted-decal path rather than stretching a crack over the outline box or original material UV. The overlay uses the verified multiplicative blend, alpha discard, `LessEqual` depth test, disabled depth writes, and crumbling depth bias. Abort, target change, completion, and reset clear it without remeshing terrain.

Completed Survival breaks are locally predicted to the exact-version default `minecraft:air` state. That copy-on-write semantic update reaches collision and renderer immediately and is tracked in a bounded 32-entry sequence queue. A matching authoritative block update confirms it; a differing authoritative state replaces it and is logged as reconciliation/rollback; Block Changed Ack retires processed predictions after any preceding authoritative correction. Placement remains deliberately server-authoritative: Phase 19 has no authoritative held-item/stack state from which it could safely derive the placed runtime state, so Cubic does not invent a placement prediction.

Current limitations are intentional: generated exact outline/interaction shapes are not yet present for every non-colliding model; the empty-hand destroy table covers the verified common Phase 19 baseline rather than pretending Cubic knows a held tool, enchantments, effects, attributes, or every block hardness; placement/use is sent generically and reconciled from authoritative server updates because held-item state is unavailable. Phase 20 owns inventory/item state and container UI and will provide placement prediction plus the missing tool/item modifiers through the existing boundaries.
